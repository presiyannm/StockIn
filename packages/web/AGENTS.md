# packages/web

The phone app the person at the door uses. React 19 + TanStack Start/Router + Tailwind 4,
built with Vite on :5173. It talks only to `packages/api`; project-wide rules are in the root
`AGENTS.md`. The UI started as a Lovable export, so the build keeps
`@lovable.dev/vite-tanstack-config` (see the comment in `vite.config.ts` before adding plugins).

## How it reaches the api

- All calls use relative `/api/...` paths. In dev, Vite proxies `/api` to `http://localhost:3001`
  (`vite.config.ts`). Photo URLs come from the api as-is: relative `/api/files/...` with local
  storage, or presigned R2 URLs.
- The contract is the API table in the root `README.md`. Response types live in
  `src/lib/api/types.ts` (snake_case, as on the wire). Do not import `@stockin/shared`; that is the
  api <-> ai-service contract.

## Files (`src/`)

| Path | What it does |
|---|---|
| `lib/api/client.ts` | One function per api route; throws `ApiError` (`status`, parsed `body`) |
| `lib/api/queries.ts` | react-query hooks and `useDeliveryAction` (runs a call, toasts errors, refetches) |
| `lib/rows.ts` | `productRows`: groups saved lines, scans, findings and issues per product (unit-tested) |
| `components/product-picker.tsx` | Pick a catalogue product or create one (unknown barcodes, unmatched lines) |
| `routes/` | File-based routes; `routeTree.gen.ts` is generated by `vite dev`/`build`, do not edit it |

Flow: `/` → `/receive/invoice` → `/receive/scan` → `/receive/reconcile` →
`/receive/issue/$productId` → `/receive/report` (confirm, finish, print). Plus `/stock`, `/history`.

## Rules

- **Show saved data, compute nothing that matters.** Comparison (findings), stock split
  (`items` on `GET /api/deliveries/:id`) and the report all come from the api. The UI only groups
  and displays them. Never add client-side stock or reconciliation logic.
- **Report on every product**, including perfect matches (BR-04).
- **Nothing the AI suggests is applied silently**: invoice lines are reviewable, a photo
  identification needs a tap to confirm.
- The supplier report is read-only and English; printing does not send it anywhere.
- There is no offline/demo mode. If the api is down, screens show the error.

## Verify

```bash
npm run typecheck -w @stockin/web
npm test -w @stockin/web
```

For flow changes, run `npm run dev` from the root and walk a delivery at http://localhost:5173.
